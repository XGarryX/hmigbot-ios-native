## 安装与初始化

在工具目录执行，目标使用开发者自己的转换工作区：

```sh
PYTHON=python3 sh install.sh /absolute/conversion-workspace
```

安装后在工作区重新打开会话，使用 `$a2h-run`。源 iOS 工程与目标工作区须互不包含；安装与升级不会改写业务源、Spec 或原执行账本。详见 [安装和升级](docs/INSTALL.md)。

初始化先展示准备使用的能力、用途、读写范围、授权方法和不开启时的替代路径。Xcode MCP 由开发者选择；只读访问范围与服务是否支持写工具分别说明。暂不开 MCP 可继续 Xcode CLI 和文件分析，缺少的原生证据保持未验证。设备和视觉观察按实际任务、选择及授权调用。

## 基本转换流程

1. **Init**：识别源/目标、当前工程配置和本次所需运行能力；不检查无关平台或未选后端。
2. **Spec**：共用一份 Source/facts，读取真实编译成员、Swift/ObjC/混合条件视图、资源和源行为，生成有源锚点的规格与 AC。
3. **Plan**：核对规格、接口、写权和真实依赖，`plan-ir` 校验后冻结；`plan-check` 是可选预览，单任务批次合法。
4. **Execute**：消费冻结合同，由 Garry indexed 流程执行资源、UI、Base、Slice；唯一回写链保留原引擎结果与严格回读。
5. **Verify**：按实际范围核对构建、静态、占位和身份；页面/路由按适用性加入，视觉/设备明确选择后调用。始终允许生成 partial/not_run 报告，未执行不算通过。

具体行为、错误处理、资源缺件、写冲突和当前证据失效仍影响对应消费者。格式偏好、无关文件、重复审批和机械修复轮数不作为通用产品门禁。完整规程见 [工作流](docs/WORKFLOW.md) 和 [能力选择说明](docs/integration/CAPABILITIES.md)。

转换进度统一查看目标工程的 **`spec/reports/ios-progress.md`**。实际写入命令开始、结束或失败时更新同一份可读记录，源分析沿用原步骤回调；详细证据仍在该工程的 `spec/` 内。只读预览/审计不更新进度，进度写入失败不改变原命令结果，也不新增转换门禁。不会在用户级 `.codex` 下创建转换进度目录。

按明确应用和模拟器范围，可选用官方应用截图、控件查询和固定回放；桌面接管保持禁止。iOS 使用 XCTest/XCUIAutomation，鸿蒙优先使用已安装的官方模拟器 CLI，所需能力不可用时再按范围使用 Hypium。双端对比、变化范围复查和实际用时计量见 [应用 UI 验证规程](docs/APP-UI-VALIDATION.md)。未选 UI 后端不阻断基本转换；截图或视觉相似不代表业务验收通过。

0.13.5 增强两个执行环节：子任务完成支持可信原生终答并继续验产物；UI 批次和功能组的资源改为任务增量提交、唯一收尾者合并，冲突在落盘前报告。命令及恢复规则见 [资源增量协议](skills/a2h-execute/references/resource-deltas.md) 和 [Join 协议](skills/a2h-join/SKILL.md)。

B0–B3 进一步接入持续补位、独立基础任务并行、页面状态/子内容交付、行为效果检查和实际修复复查。全流程计量会留下本轮耗时与构建/返工等记录，规则见 [重跑与计量](skills/a2h-run/references/execution-measurements.md)。旧项目需新冻结或按原受审恢复，不沿用旧 PASS。

## 本版实现选择

- **本地 Git**：源证据、实际构建配置、条件编译、规格/计划合同、权限选择、因果诊断与部分报告。
- **Garry .32**：择优采用原生 UI 显隐采集、执行回写协议，以及已接线的 indexed 执行和目标检查。
- **共享实现**：源事实、正式输入身份、活动代码视图、资源引用和构建证据只保留一份权威实现，减少重复解释和重复运行。

详细来源、采用/保留可选/剔除理由及官方依据见 [择优融合说明](docs/SELECTIVE-FUSION.md)。源语法和工程证据优先使用 Apple Xcode CLI/MCP、Swift 官方库及 Apple 分发的 Clang；本工具的编排与跨平台映射如实标为自编适配。

## 发行边界

发行选择与安装选择共用 `payload_layout` 的 macos-arm64 profile。只发布转换运行代码、通用模板、schema、必要运行依赖、许可与来源说明。项目现场、测试夹具/结果、日志、缓存、归档和维护评估保存在工具目录外；目标工程需要的通用测试模板仍属于转换模板。

按 `scripts/package_plugin.py` 生成 ZIP，使用 `scripts/verify_package.py` 对照外部清单验证。ZIP、校验清单和任何测跑结果均写到工具目录外。发布文件完整性与具体 App 的转换验收分开记录。
