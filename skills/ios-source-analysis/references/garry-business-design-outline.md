# 业务与设计补充提纲

来源：Garry 1.5.2-mac-20261024.14 的 a2h-ios-analyzer 角色。
此提纲是补充覆盖检查，只在已分配的参考文档范围内采用；正式章节、事实、源责任、AC 与审批均以本包 Git 规格合同为准，不替代 source-check --harness 或生成门禁结论。

## Phase 2: Generate spec.md

输出 {project_name}_spec.md，保留以下原编号及其必要内容；没有相关实现时写明并保留标题。

1. 应用定位：核心职责、输入、输出、边界；解释性的判断标 [推断]。
2. 领域术语：实际模型、枚举、状态、标识、常量与业务含义，不预设术语数量。
3. 角色与边界：用户角色、外部服务、系统与 SDK 接缝、交互上下文；可用 PlantUML。
4. DFX约束：性能、并发/缓存/取消、安全、凭据与隐私、最低系统及兼容性；区分事实与建议。
5. 核心能力：使用三级标题 5.X {能力名}；每项有业务规则、交互流程、异常场景。沿真实入口→校验→操作→结果描述，包含错误、重试、取消、边界和恢复；必要时给触发→预期验收条件。
6. 数据约束：真实实体字段/类型/默认值/可空/编码、关系、UserDefaults与Keychain键、文件/URI格式、枚举取值。保留自定义解码失败顺序，不能将源码未触达的兼容分支描述为有效容错。
7. 用户界面行为规格：屏幕流转、视图模式、手势、对话框、搜索筛选、排序分组；页面与组件分开，路径可追溯。
8. 偏好设置行为规格：分组、控件、实际存储键、默认值、值域、即时/重启生效与联动。
9. 文件格式与数据交换规格：实际存储、导入兼容、导出、分享及失败处理。
10. 本地化与无障碍需求：语言/复数、Dynamic Type、VoiceOver与源码实际可见约束。
11. 平台行为规格：权限、通知、Widget/实时活动等系统集成、后台任务、备份恢复；明确本轮选定/延期的部分。

## Phase 3: Generate design.md

输出 {project_name}_design.md，保留原编号：

1. 概述：应用定位和核心交互。
2. 功能清单：以实际领域、入口、实现模块与依赖组织。
3. 实现模型：上下文、总体架构、真实 target/SwiftPM 模块；3.4设计系统包含色彩、主题、字体、尺寸间距、图形资源、动画；后续逐模块说明职责、文件结构、类/时序/数据关系、用例、接口、核心算法、错误处理。
4. 接口设计：内部数据访问、业务抽象、后台/平台任务、动作与URL协议、文件交换接口。
5. 数据模型：与 spec §6 对应的真实字段和关系，记录编码/解码约束。
6. UI设计系统：色彩、深浅色主题、排版、尺寸间距、图形资源和动画，可引用3.4避免重复。
7. 屏幕清单与导航：页面类型、入口、功能、参数、返回及深链；与 spec §7 一致。
8. 用户交互规格：操作、对话框、剪贴板、反馈、空态和加载态。
9. 平台集成：实际构建配置与依赖版本、权限、系统服务、通知/扩展、备份。
10. 偏好设置目录：与 spec §8 同一键、默认值、值域和副作用。

本文件描述源实现事实与迁移所需契约，不在参考分析阶段生成 ArkTS 实现，也不复制大段页面源码充当设计。

## Phase 4: Self-Validation

核对 spec §6↔design §5实体、spec §5↔design §3领域、spec §8↔design §10偏好、两份 §7页面与导航。检查所引用文件真实存在且属于选定源。正文注明来源与局限，不把静态推断写成运行证据。
