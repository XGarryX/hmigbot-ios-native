# 同宿主恢复登记

## 前提

登记属于用户授权的真实恢复操作。先回收当前任务，等全部代理控制调用的真实返回落盘，再单独调用完整 `list_agents` 确认旧子任务不再活跃；不能将派发和这次完整列表并行。将完整失败工程归档到项目外；核对归档逐文件 SHA-256，保留原日志和旧失败审计。恢复事先核验的空工程，并安装当前新版；尚未运行 INIT。不要以已有半程工程登记。

所需包外清单均使用实际文件计算，不手填通过结果：

- 空备份清单：`workspace`、`backup`、`files`（相对路径 → SHA-256）。
- 在批准该空备份时另行保留清单文件自身的 SHA-256。不能在失败后把半程工程重新命名成空备份并现场认可其哈希；空备份不得包含 spec、迁移配置、已装工具或工作产物目录。
- 本次失败工程归档清单：`workspace`、`archive`、`files`。
- 清单和输出目录独立于工程、原空备份和归档目录。

## 登记

在安装后的项目内使用 `.hmigbot-ios/plugin/scripts/join_attempt.py`（下称脚本）。先调用 `seal --project <绝对路径> --pristine-manifest <空备份清单> --pristine-sha256 <事先批准的清单SHA> --archive-manifest <归档清单> --out <项目外新receipt.json>`。脚本核对完整备份、完整归档和恢复后安装文件集。实际宿主完整历史另存只读快照及审计；历史失败仍保留 exit 1 和未收口数量。

读取 seal 实际返回的 receipt SHA，生成唯一 32 位小写十六进制 nonce，再用一个独立宿主工具调用执行：`python -B <脚本> begin --project <绝对路径> --receipt <receipt.json> --receipt-sha256 <实际SHA> --enrollment <nonce>`。该调用仅运行这一个进程，不混入其他命令或批次。在原始工具输出中保留进程 `exit_code` 及完整 JSON 输出。nonce 及 SHA 作为该次调用的明确参数，仅使用一次；不在后续命令中复制重发。使用宿主实际提供的 `CODEX_THREAD_ID`，禁止手动覆盖或借用其他线程身份。

实际命令须由 Python `shlex.join` 对完整 argv 生成：`python`（Mac 可用 `python3`）、`-B`、本安装脚本的真实绝对路径、`begin`，随后四个必需选项各出现一次。禁止复合命令、重定向、换行、环境前缀及额外选项。宿主若使用 `functions.exec` 包装，输入必须是单条 `text(await tools.exec_command(<JSON 字面量>));`，JSON 使用双引号键，仅含 cmd/workdir/login/max_output_tokens/yield_time_ms/tty 等正常进程选项；不能用变量、额外 JS 或手填返回对象。直接 `exec_command` 使用同一规范命令。应给独立进程充分的等待时间并保留完整回执；尚无可核验退出码、回执缺失或不明确时不能将它当作可忽略失败，也不能改用新 nonce 试图移过边界。

进程参数明确设置 `yield_time_ms: 30000`（固定值）、`max_output_tokens: 6500`、`tty: false`，建议 `login: false`。脚本路径必须与安装后的规范绝对路径字符串相同，不能使用相对路径、别名或符号链接。functions.exec 必须在首行使用唯一元数据注释 `// @exec: {"yield_time_ms":60000,"max_output_tokens":6500}`，随后为上述单条调用，避免宿主包装先于进程返回而提前 yield；元数据严格使用该 ASCII 格式、两键顺序及无前导零的单行整数，不接受重复键或其他行终止符。

若原始进程回执只有 `session_id`，继续轮询该真实进程，不重新运行 begin。每次轮询必须是独立的 `text(await tools.write_stdin(<JSON 字面量>));`（或直接 write_stdin）；只含原 session_id、空 chars 及正常等待/输出预算，实际推荐明确设置 yield_time_ms=10000、max_output_tokens=6500，使包装层能及时获得完整回执；门禁允许 max_output_tokens 缺省（当前宿主工具协议默认为 10000）或不少于 4096。不得向登记进程写入输入、并行轮询、使用变量或混合其他调用。门禁按原始调用顺序拼接同一进程的 stdout，直到原宿主返回实际 exit_code；其他原始工具输出若再次声明该 session_id 则拒绝，不能借用其他进程或 stdout 内的 JSON 来补退出码。本入口依赖当前宿主在进程仍运行时返回整数 session_id。若外层 exec 本身先 yield 而没有原进程回执，或续取回执格式未知，本版拒绝且停止登记；该原调用不能作为成功或已结束的失败，不能在同一线程改用新 nonce/seal 越过它。须保留日志排查工具/宿主问题，不能手填结果。

begin 在工程 `.migbot/join-attempt.json` 写入真实 call_id、字节行尾、前缀 SHA、receipt 绑定、实现 SHA、历史失败摘要。调用或末行尚未完整记录时有界等候，仍不可读则拒绝；不能裁剪该行或构造补充记录。Gate 要求该调用已有对应成功进程输出，尚未落盘时稍后重跑 Gate。只有原宿主输出明确记录非零进程退出码且未输出本 nonce 的 created 状态时，才保留为失败记录并排除出成功登记链；修正输入后以新 nonce 重新登记，不复用旧 nonce。已写出 created 后又非零退出、缺输出或含义不明均不能按可忽略失败处理。

后续每次验证会从原始登记调用行之前的完整前缀，重新检查所有代理控制已返回及随后的完整空闲观察；不借用登记之后才出现的列表。未知 custom 代理控制格式在历史恢复、登记空档及当前尝试中均拒绝，不能漏计。

旧快照之前形似 begin 的非规范命令作为 foreign 历史诊断保留，不能授权登记。当前 seal 之后再出现非规范登记时拒绝继续。若尚无 STATE/INIT 产物、工程仍与核验恢复树完全相同，可重新 seal，将先前失败纳入新快照；不得复用旧 receipt 或删除旧日志。已有 STATE 或半程材料时必须按授权完整归档恢复。

## 后续门禁

INIT 后所有真实派发必须有新的唯一任务名。保持 expected-set、真实 completed 观察、产物契约及 join 点；Gate 和 audit 自动使用已核验的尝试范围。历史同名任务、迟到旧调用和仍活跃旧子任务不能污染当前尝试。原日志每一行仍完整解析，损坏前缀不能被边界掩盖。

恢复前及当前最后一次派发的真实返回落盘后，都要再次单独调用覆盖当前派发者整棵子树的完整 list_agents；只含窄 path_prefix 或其他筛选参数的结果不能证明全部空闲或取代完整观察。原始控制调用仍缺返回时不能登记。派发明确失败时仍须补派同一请求任务并观测完成，不能用其他任务完成来抵消；无可识别任务名的失败需停止排查。列表调用失败或条目损坏时保留诊断，不作为完整空列表；须在错误返回之后重新获取有效完整列表才能继续。每次登记门禁重新核对安装归属文件的实际字节，修改工具后须走授权恢复。

begin 是一次宿主调用，不承诺 CLI 重入；已有状态应由 Gate 继续读取，不要用第二个工具调用再运行 begin。bootstrap 不重建状态。状态删除、实现更换、receipt/原日志前缀变化或额外成功/未定登记均失败，不选择更晚时间来跳过当前任务。seal 与 begin 之间不能派发、重启或等待其他代理工作，seal 的历史快照也不能包含 begin 调用本身。

如新工具缺陷迫使再次恢复，先依据已有用户授权或取得所需授权，完整归档当前尝试及其状态，再恢复核验空工程并安装修复版。新 receipt 保留归档中的上一 attempt 状态，形成可追溯链；先前调用及其失败始终留在完整历史中。直接删状态并重登不能建立此链。

此机制不判定业务行为、不代替编译或阶段审批，也不修改原日志或将旧失败改记为成功。
