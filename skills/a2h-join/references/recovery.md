# 同宿主恢复登记

## 前提

登记属于用户授权的真实恢复操作。先回收当前任务，等全部代理控制调用的真实返回落盘，再单独调用完整 `list_agents` 确认旧子任务不再活跃；不能将派发和这次完整列表并行。将完整失败工程归档到项目外；核对归档逐文件 SHA-256，保留原日志和旧失败审计。恢复事先核验的空工程，并安装当前新版；尚未运行 INIT。不要以已有半程工程登记。

所需包外清单均使用实际文件计算，不手填通过结果：

- 空备份清单：`workspace`、`backup`、`files`（相对路径 → SHA-256）。
- 在批准该空备份时另行保留清单文件自身的 SHA-256。不能在失败后把半程工程重新命名成空备份并现场认可其哈希；空备份不得包含 spec、迁移配置、已装工具或工作产物目录。
- 本次失败工程归档清单：`workspace`、`archive`、`files`。
- 清单和输出目录独立于工程、原空备份和归档目录。

## 登记

在安装后的项目内使用 `.agents/hmigbot-runtime/scripts/join_attempt.py`（下称脚本）。先调用 `seal --project <绝对路径> --pristine-manifest <空备份清单> --pristine-sha256 <事先批准的清单SHA> --archive-manifest <归档清单> --out <项目外新receipt.json>`。脚本核对完整备份、完整归档和恢复后安装文件集。实际宿主完整历史另存只读快照及审计；历史失败仍保留 exit 1 和未收口数量。

读取 seal 实际返回的 receipt SHA，生成唯一 32 位小写十六进制 nonce，再用一个独立宿主工具调用执行：`python -B <脚本> begin --project <绝对路径> --receipt <receipt.json> --receipt-sha256 <实际SHA> --enrollment <nonce>`。该调用仅运行这一个进程，不混入其他命令或批次。在原始工具输出中保留进程 `exit_code` 及完整 JSON 输出。nonce 及 SHA 作为该次调用的明确参数，仅使用一次；不在后续命令中复制重发。使用宿主实际提供的 `CODEX_THREAD_ID`，禁止手动覆盖或借用其他线程身份。

实际命令须由 Python `shlex.join` 对完整 argv 生成：`python`（Mac 可用 `python3`）、`-B`、本安装脚本的真实绝对路径、`begin`，随后四个必需选项各出现一次。禁止复合命令、重定向、换行、环境前缀及额外选项。宿主若使用 `functions.exec` 包装，输入必须是单条 `text(await tools.exec_command(<JSON 字面量>));`，JSON 使用双引号键，仅含 cmd/workdir/login/max_output_tokens/yield_time_ms/tty 等正常进程选项；不能用变量、额外 JS 或手填返回对象。直接 `exec_command` 使用同一规范命令。应给独立进程充分的等待时间并保留完整回执；尚无可核验退出码、回执缺失或不明确时不能将它当作可忽略失败，也不能改用新 nonce 试图移过边界。

进程参数明确设置 `yield_time_ms: 30000`（固定值）、`max_output_tokens: 6500`、`tty: false`，建议 `login: false`。脚本路径必须与安装后的规范绝对路径字符串相同，不能使用相对路径、别名或符号链接。functions.exec 必须在首行使用唯一元数据注释 `// @exec: {"yield_time_ms":60000,"max_output_tokens":6500}`，随后为上述单条调用，避免宿主包装先于进程返回而提前 yield；元数据严格使用该 ASCII 格式、两键顺序及无前导零的单行整数，不接受重复键或其他行终止符。

若原始进程回执只有 `session_id`，继续轮询该真实进程，不重新运行 begin。每次轮询必须是独立的 `text(await tools.write_stdin(<JSON 字面量>));`（或直接 write_stdin）；只含原 session_id、空 chars 及正常等待/输出预算，实际推荐明确设置 yield_time_ms=10000、max_output_tokens=6500，使包装层能及时获得完整回执；门禁允许 max_output_tokens 缺省（当前宿主工具协议默认为 10000）或不少于 4096。不得向登记进程写入输入、并行轮询、使用变量或混合其他调用。门禁按原始调用顺序拼接同一进程的 stdout，直到原宿主返回实际 exit_code；其他原始工具输出若再次声明该 session_id 则拒绝，不能借用其他进程或 stdout 内的 JSON 来补退出码。本入口依赖当前宿主在进程仍运行时返回整数 session_id。若外层 exec 本身先 yield 而没有原进程回执，或续取回执格式未知，本版拒绝且停止登记；该原调用不能作为成功或已结束的失败，不能在同一线程改用新 nonce/seal 越过它。须保留日志排查工具/宿主问题，不能手填结果。

begin 在工程 `.migbot/join-attempt.json` 写入真实 call_id、字节行尾、前缀 SHA、receipt 绑定、实现 SHA、历史失败摘要。调用或末行尚未完整记录时有界等候，仍不可读则拒绝；不能裁剪该行或构造补充记录。Gate 要求该调用已有对应成功进程输出，尚未落盘时稍后重跑 Gate。只有原宿主输出明确记录非零进程退出码且未输出本 nonce 的 created 状态时，才保留为失败记录并排除出成功登记链；修正输入后以新 nonce 重新登记，不复用旧 nonce。已写出 created 后又非零退出、缺输出或含义不明均不能按可忽略失败处理。

后续每次验证会从原始登记调用行之前的完整前缀，重新检查所有代理控制已返回及随后的完整空闲观察；不借用登记之后才出现的列表。未知 custom 代理控制格式在历史恢复、登记空档及当前尝试中均拒绝，不能漏计。

旧快照之前形似 begin 的非规范命令作为 foreign 历史诊断保留，不能授权登记。当前 seal 之后再出现非规范登记时拒绝继续。若尚无 STATE/INIT 产物、工程仍与核验恢复树完全相同，可重新 seal，将先前失败纳入新快照；不得复用旧 receipt 或删除旧日志。已有 STATE 或半程材料时必须按授权完整归档恢复。

安装布局升级时，历史行按原 receipt 链各代 `history.bytes` 的完整行边界及唯一 owned 登记脚本解释；原脚本字节须与下一代归档、原安装清单 SHA 一致。当前 seal 之后仍只接受当前规范入口，不允许复制旧入口作为别名。历史 foreign/failed 审计必须原样复现；若旧 foreign 原因依赖当时缺失的文件、无法复现，仍拒绝恢复，不改写旧审计。无 STATE 时旧规范入口也只用于检查状态丢失，不能建立新登记或范围。

归档缺少上一 STATE 时，已知旧布局的同工程 active 调用仍阻断 seal；沿用原 active/failed 判定，不以改换目录掩盖状态丢失。此兼容要求历史链未包含曾漏掉该检查而跨布局的旧收据。只有明确失败的旧布局调用且无历史 STATE 时，不阻断恢复；因当前唯一规范路径已改变，这类调用在新快照中作为 foreign 保留，不授权其为新登记。

## 后续门禁

INIT 后所有真实派发必须有新的唯一任务名。保持 expected-set、真实 completed 观察、产物契约及 join 点；Gate 和 audit 自动使用已核验的尝试范围。历史同名任务、迟到旧调用和仍活跃旧子任务不能污染当前尝试。原日志每一行仍完整解析，损坏前缀不能被边界掩盖。

恢复前及当前最后一次派发的真实返回落盘后，都要再次单独调用覆盖当前派发者整棵子树的完整 list_agents；只含窄 path_prefix 或其他筛选参数的结果不能证明全部空闲或取代完整观察。原始控制调用仍缺返回时不能登记。派发明确失败时仍须补派同一请求任务并观测完成，不能用其他任务完成来抵消；无可识别任务名的失败需停止排查。列表调用失败或条目损坏时保留诊断，不作为完整空列表；须在错误返回之后重新获取有效完整列表才能继续。每次登记门禁重新核对安装归属文件的实际字节。同一尝试内的工具修复升级，使用下节经真实宿主回执核验的升级入口；没有合格升级证明时，不豁免实现变化。

begin 是一次宿主调用，不承诺 CLI 重入；已有状态应由 Gate 继续读取，不要用第二个工具调用再运行 begin。bootstrap 不重建状态。状态删除、未有合格升级回执的实现更换、receipt/原日志前缀变化或额外成功/未定登记均失败，不选择更晚时间来跳过当前任务。seal 与 begin 之间不能派发、重启或等待其他代理工作，seal 的历史快照也不能包含 begin 调用本身。

只有确需恢复整个尝试时，先依据已有用户授权或取得所需授权，完整归档当前尝试及其状态，再恢复核验空工程并安装修复版。修复仅影响后续步骤时按用户指定的最早受影响断点续跑，不因工具升级清空前面阶段。新 receipt 保留归档中的上一 attempt 状态，形成可追溯链；先前调用及其失败始终留在完整历史中。直接删状态并重登不能建立此链。

此机制不判定业务行为、不代替编译或阶段审批，也不修改原日志或将旧失败改记为成功。

## 同一尝试内升级工具

用于已授权的通用工具修复；不会建立新 attempt，也不代替阶段审批。原 join-attempt.json 字节、登记调用、start_bytes、prefix、receipt 链、备份、归档及历史失败保持不变。升级后 Gate 仍从原始起点检查全部派发、真实 completed 和产物契约。没有升级时原流程不增加材料。

先将候选包冻结，在项目外生成包清单：使用候选 `hmigbot_ios152.join_upgrade.package_inventory(<候选绝对路径>)` 的真实结果保存 JSON，并计算文件 SHA-256。它对应正常安装器的全部实际 payload。保留原登记版本的真实分发包；升级入口会将其完整归属文件逐项与原 receipt 核对。所有代理控制返回后，单独获取完整 list_agents，确认子任务已停止；升级进程运行期间不派发或控制其他代理。

使用候选包的规范绝对 `scripts/join_attempt.py`，由实际原 root 线程执行一个独立进程：`python3 -B <候选脚本> upgrade --project <项目绝对路径> --origin-package <原登记包绝对路径> --package-manifest <包外候选清单> --package-sha256 <实际清单SHA> --evidence-root <包外全新目录> --upgrade <唯一32位小写十六进制nonce>`。argv 用 shlex.join 生成。原生调用使用与 begin 相同的 literal exec 包装、yield_time_ms=30000、max_output_tokens>=4096、tty=false；若是 functions.exec，使用上文规定的完整结果元数据。进程尚在运行时只轮询同一 session 的真实结果，不重新执行 upgrade。

升级进程先验证完整原恢复证据和历史，冻结当前安装的全部 owned 字节与清单，再由正常安装器事务升级并核验新清单/实际文件。原实现来自经过 SHA 核对的冻结字节，在隔离 Python 中只读重放同一区间；逻辑入口路径仅从原 receipt 和真实 begin argv 推导，不安装或覆盖旧实现。新审计不能丢失旧未收口或失败观察。原调用的成功输出绑定包外按内容寻址的 receipt 和项目 hashed pointer；每次 Gate 仍核对当前完整安装字节，不能只改版本号。既有中间版本若缺同期升级记录，只如实记录本次对既有安装的重新核验，不补写过去事件。

回执、其冻结材料和指针应保留；原分发目录在完整验证并生成升级回执后可移走。多次升级只追加链，禁止降级。Gate 按原宿主真实成功调用核对链末端，不能把指针退回旧回执，也不能在缺失/模糊退出结果时继续。升级后不再 begin/seal 改变范围。升级拒绝时保留原工程、状态和失败证据，报告确切原因；不能伪装空恢复或清空前面阶段来通过门禁。

差异材料须如实包含原版到当前版的实际代码差分；其中可能含先前版本已有的 fork inherited-context 处理，不能将所有差异都称为本次 epoch 兼容。升级差分还保留原非零审计、无效列表及最后完整列表顺序、failed/unjoined 和 fake ledger 观察，不能因新实现少报而转绿。该差分调用未提供 ledger 时，fake ledger 项实际为空并标明未审计 ledger；不为升级新增必需 ledger。
