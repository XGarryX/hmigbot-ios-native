# 工具修复与项目转换分开记账

适用于工具开发、安装升级、门禁审计、原生迁移及复盘。先确认当前聊天的写入范围和唯一 owner；跨聊天同步需遵循宿主授权。

1. **工具结果**只记录可复用代码、规则、模板、安装和发布能力。列权威工具源根、版本、文件摘要、实际命令、退出码和回归证据。隔离候选、单测通过、发布、安装、项目实测分别记录，不能互相替代。
2. **项目结果**单列源快照、selected build、graph/obligation 摘要、AC/决策、门禁及生成/编译/行为/视觉证据。工具测试通过不增加任何项目转换进度；spec-check PASS 只证明该检查范围。
3. **问题归属**逐条标明工具缺陷、项目派生资料过期、真实产品待决/缺口、环境失败或尚未判明，并附复现证据。项目旧 unknown 不自动证明新提取器仍缺能力；反过来不能仅改分类或删除义务宣称工具阻断为零。
4. 二进制 plist 由 plist 格式解析器读取；资源保留事实和义务，不按 Preview 排除，也不宽松解码伪装成源码。Swift、Objective-C/Objective-C++、C/C++、IB、构建证据按各自合同消费。二进制资源语义证据使用 resource_document 坐标及原字节 SHA-256；不得把该坐标当物理文本行。
5. 库内部、测试目标、批准替代及源历史只能通过精确、当前、独立复核的 source responsibility 合同投影。保留原始事实、义务、源 unknown 与历史 AC；应用公开调用、存续状态/错误/清理仍按普通合同验收。没有完整可重放可达性证据时，unused 标签或“没找到调用”不能证明死符号。
6. 门禁只读审计使用 spec-check 与 source-check --harness --report-only，并记录检查前后输入摘要。存在并发修改则标明该结果不稳定并重跑。正式落账、AC/决策补全与转换归项目 owner；只有原工具写控制账本。
7. 升级交接给出主目录、版本/包摘要、变更范围、安装命令、失效的旧图/计划及重跑顺序。项目 owner 重新生成受影响派生事实、重审 source responsibility/semantics/coverage，再执行正式门禁。PASS 后才进入依赖它的 plan/execute；没有实际运行不声称转换确认完成。

报告必须分别列“工具：已合入/已发布/已安装/已项目实测”和“项目：规格/门禁/生成/编译/行为/视觉”。审计报告是证据，不另造迁移状态账本。

升级前先做所有权与用户编辑预检，再在项目内归档并清理内容可识别的旧机器派生文件；清理不是转换进度，不删除作者规格、AC/决策、source-index、源语义/coverage/responsibility、原始证据或控制账本。安装失败回滚恢复，成功后按原variant/provider重新生成并重跑门禁。

macOS二进制调用的隔离属性修复只允许当前明确转换项目内的目标；校验完整子树、链接与实际退出码。不得对项目外源工具、临时runtime、HOME或系统根执行xattr；原launcher隐式调用同样受此限制。
