# probe 错误 → 修法知识库

沿用 [probe-runbook.md](probe-runbook.md) 的错误归类与有界循环。以下是错误模式和候选来源，不是任意 iOS 项目的后端事实；实际取值必须从本轮 Source、真实 Release 配置、contract 或已批准决策取得。未知字段、账号、密钥和服务端枚举不能靠重复发送猜出。新模式按原 novel 机制记录并冒泡。

| 症状 | 归类 | 诊断与取证 |
|---|---|---|
| -401 / 版本或身份拒绝 | 有真实候选则客户端可调，否则 MISSING-TRUTH | 核对已绑定 Release 设置、Bundle/Info.plist、实际业务配置及签名输入；不猜版本、渠道、bundle 或平台枚举 |
| -500 / 某枚举、归因、映射为 null | 候选可证明才客户端可调；无来源则后端侧 | 先逐字段对齐真实请求和已知分发配置；相同输入仍被拒则找后端规则，不复制别的项目渠道 |
| NOT NULL / 缺字段 | 有真实源字段则客户端可调，否则 MISSING-TRUTH | 核对实际字段、类型、来源、权限及生命周期；不能为满足非空而发随机值、全零或空字符串 |
| 请登录 / token 无效 | 视实际端点而定 | 按 auth_model 区分确需鉴权与实际公共/初始端点；没有测试凭据或合法 bootstrap 证据则停止并记录联调缺口 |
| 解密失败 / 参数解析异常 | MISSING-TRUTH 或有证据的客户端编码问题 | 对齐真实密钥/IV/模式/编码的字节来源；封装在不可读 xcframework/库或被掩码时不猜值 |
| 签名指纹 / safe-env 拒绝 | 有源契约与真实证书材料则客户端可调，否则后端侧 | 先确认真实 Swift/Objective-C 如何生成并提交指纹；源与目标签名材料不同，不能套用其他平台证书导出公式，也不能假称服务端已接受目标证书 |
| 所有初始端点都要求 token | 后端侧 / 联调 | 明确新客户端如何获取初始身份；停止盲试，把环境、样本与问题交给后端 |
| sign invalid / 明确签名错误 | 有真实算法和输入则客户端可调 | 核对键序、注入次序、UTF-8、hex/base64、时间窗与 nonce；用已授权样本/golden 逐字节对照 |

HTTP 200 不等于业务成功。按真实成功码和响应层级判断，错误或缺失响应不能销账。参考模式只提供定位方向，不证明本项目存在设备绑定、特定字段长度或相同登录/注销语义。
