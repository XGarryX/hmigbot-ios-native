# 原生 iOS 迁移决策 C0–C17

本清单保持 HMigBot decision-ledger 的类目与 D0/PD/D 编号契约。
先核对本轮用户要求与已批准决策；范围、约束未变时直接复用，不重复审批。
源码能确认的写事实；目标官方文档能确认的写技术结论；只有无法推导的产品取舍才问用户。
不存在的能力写不适用，未知事实写缺口，不能为了清单完整臆造某类业务。

| 类目 | 核验问题 | 源证据与处理 |
|---|---|---|
| C0 产出定位 | 本轮要求实现到哪种可验收状态？ | D0 明确范围、必须真实的核心流程与验收；已要求完整迁移不得擅降为演示 |
| C1 初始/增量 | 有效 baseline 是否存在？ | 比较源指纹与既有 AC；续做保留稳定 ID |
| C2 范围 | app、extension、targets、模块的哪些行为在范围？ | 工程成员与功能清单逐项认领，不把框架扫描命中当完整性 |
| C3 目标平台 | SDK/API 与设备形态是什么？ | 读真实目标配置；iPhone/iPad、窗口与方向事实只用于约束目标 |
| C4 横切能力 | 多语言、深色、动态字体与辅助功能有哪些？ | xcstrings/strings、asset appearance、Environment/trait、accessibility；未检出不等于不存在 |
| C5 未达代码 | 测试、预览、禁用分支与动态入口怎么处置？ | target membership、路由、反射、配置；引用数为零不是死码证明 |
| C6 系统能力替代 | Apple 能力有无语义相当的目标 API？ | 读 entitlement、plist、调用链和目标版本文档；缺对等项提出行为替代 |
| C7 架构 | 状态所有权、并发、持久化、导航如何落地？ | 保留源 Swift/ObjC 生命周期约束；影响全局的选择写决策与 AC |
| C8 三方依赖 | 是否有可用鸿蒙版本或替代？ | Package.resolved/Podfile.lock/二进制清单 + 实际用法；查完整随包 SDK 文档、厂商官网 |
| C9 UX 差异 | 系统交互变化是否改变用户可观察行为？ | sheet、导航返回、picker、键盘、无障碍，标明受影响页面/AC |
| C10 后台/长任务 | 中断、恢复、取消与扩展边界是否保留？ | scene phase、task、BGTask、音视频与目标生命周期分别分析 |
| C11 失败策略 | 拒绝权限、离线、超时、错误和重试怎么处理？ | 按源分支与契约核验；不得以空 catch 或假成功代替 |
| C12 原版缺陷 | 是否要求同时修正已证实缺陷？ | 默认忠实已确认行为；业务变更与迁移分开记录 |
| C13 签名/发布 | 哪些构建、签名与安装条件可用？ | 未签 IPA、签名 HAP、安装与运行分别记状态；普通账户限制据实际工具结果 |
| C14 身份/配置 | bundle、URL scheme、关联域、权限、服务端标识如何迁移？ | plist/entitlements/config → 目标配置；不把账户或平台标识直接冒充等价 |
| C15 验收范围 | 每条 AC 由什么证据判定？ | static/unit/contract/route/ui/visual/device 强度保持；无设备保持待验 |
| C16 交付边界 | 本轮完成/阻塞/保留项有哪些？ | 以实际报告、产物、日志为准；占位登记 owner 与关闭条件 |
| C17 协议不确定项 | 参数、签名、编码、认证或重试还有何未知？ | 源码可解先解；需要 trace 的标 needs_capture；产品分歧才提决策 |

## 写入与传播

1. 用 `templates/decision-ledger-template.md` 在 `spec/decision-ledger.md` 单文件累积。
2. 每条记录 ID、类目、事实、候选、选择依据、影响 page/F/AC、owner、状态和证据。
3. 平台替代写 PD-ID、替代数据流、supersedes、emits；未批准不能冒充已实现等价。
4. spec 收口产品边界，plan 将技术决定分配到 base/slice/UI packet；execute 依决策实现。
5. 验收使用决策规定的可观察结果。改变决定时保留 superseded 链，重开相关 AC。
6. 确定性修复与已有授权不重新审批。需要取舍时先提供可审查影响和可行选项。
