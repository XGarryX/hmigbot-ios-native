# 应用运行与设备验证

当前公开编号以 [编号与范围合同](check-keys-and-scope.md) 为准：视觉/运行属于 CHECK-7，CHECK-4 仍为应用身份，不沿用旧文档中的 CHECK-3 视觉、CHECK-4 单测编号。

## 调用准备与范围

只运行已经选择且有明确应用、设备/模拟器和场景的检查。复用当前任务授权，不为已确定步骤重复确认，不猜测个人真机或扩大到无关应用。没有已选 UI 运行项时不调用设备；缺失输入仅影响相应子项，基本转换、构建与报告继续。

- 源端优先 Apple 官方应用测试框架和 CLI，绑定实际 bundle ID、构建身份、模拟器、语言/主题/字号与检查点。记录的是测试系统暴露的控件信息，不是完整 SwiftUI/UIKit 内部树。
- 目标端按实际可用的官方 SDK/测试后端绑定其应用、设备及构建；某端缺件、旧构建或检查点缺失不能记成双端通过。
- 使用可观测的就绪等待和超时，保留重试/恢复记录，不在两类测试之间机械插入固定空等。
- 只验证时不改产品代码；必要测试设施放在明确的测试范围。修复依既有任务范围执行，不扩大产品授权。
- 禁止桌面远控、无关应用和系统授权设置操作；截图允许不包含录屏或未指定设备。见 runtime 的 `rules/app-ui-validation-boundary.md`。

## 视觉、控件和固定回放

当前 `ui_validation_evidence.py pair` 的 `cross_platform` 和 `assessment` 列出源码映射/唯一语义ID/文案类型推断、歧义、实际配置与关单缺口；无稳定ID也应生成候选，不用运行时widget ID充当跨端身份。完整图像相似、控件观测一致、业务通过分别判断。读树截断、配置 unknown、未匹配均不能拿空差异清单记100分；也不能把这些缺口升级为基本转换的全局门禁。逐差异豁免必须绑定当前证据并注明复核来源；单端错误弹窗保持实际应用问题。详见工具 `docs/APP-UI-VALIDATION.md`。

按当前交付的真实适配入口执行指定应用的截图、控件查询和固定场景回放；实现存在、执行发生和验收通过分别记录。旧 `arkts-visual-verify`、旧场景脚本及视觉 fixer 仍延期，不能把 Android 命令套成 iOS 实现。

每个检查点保存当前两端的应用/设备/构建/配置、截图与结构证据、实际断言、时间、摘要和结果。只有一端截图不代表完成对比，视觉相似不证明事件、导航、错误处理或持久化行为。Preview 为固定配置组件证据，不能升级为业务链路实测。

外部证据须核对版本、范围与产生工具，引用其真实来源，不冒称本工具采集。以下旧路径仅用于兼容映射，不因文件缺失要求安装旧后端：

- `spec/visual-verify/report.md`；
- `spec/fix/_state.yaml` 指向的当前 `round-N/`；
- 当前轮 `ui/`、`feat/` 中未解决的问题及 carry-forward 项。

完整范围的当前真实证据通过且无未关闭问题时才可标通过；ALIGN 等纯视觉差异、CRASH/不可达/实现缺失等功能失败分别记录。缺输入或未启动保留 DEFERRED/not_run；已执行错误保留原失败，修复代码不代表复测完成。当前公开状态按选择范围合同映射，不创建新的总流程门禁。

## 独立行为与单元测试

按明确选择调用 `arkts-ut-verifier`。仅验证任务使用 `MODE=verify_only`；已经授权修复时沿用其修复范围和原 owner。iOS 真值来自当前源码/测试/实际观察，缺失处保持未验证。

读取其实际 `spec/verify/ut/ut-report.md`、状态和当前轮摘要；没有执行修复循环时不要求修复循环专属产物。GREEN、RED、ERROR、缺证据和修复待复测分别报告，不能把已执行用例通过率当成全部业务/设计范围已验证。通过率沿用实际报告分母。
