# HarmonyOS功能定位类问题类型详解

## 问题类型分类体系

本文件详细描述HarmonyOS ArkTS应用开发中常见的8大类功能定位问题类型，为技能识别和分类提供标准化依据。

> **V1 / V2 兼容说明**：项目锁 V2，但仓库可能存在两种装饰器体系。问题识别时**关键词同时覆盖 V1 与 V2**：例如 `@State|@Local`、`@Prop|@Param`、`@Link|@Event`、`@Observed|@ObservedV2`、`@StorageLink|AppStorageV2`、`@Watch|@Monitor` 等。

## 1. 页面和导航功能定位

### 问题特征
- **关键词**：页面、界面、屏幕、路由、导航、跳转、返回
- **语义**：询问UI界面或导航逻辑的实现位置

### 典型问题模式
- **页面实现**：
  - "登录页面在哪实现？"
  - "首页界面在哪定义？"
  - "用户设置页面在哪？"
  - "关于页面在哪？"

- **导航配置**：
  - "路由配置在哪？"
  - "导航逻辑在哪实现？"
  - "页面跳转在哪定义？"
  - "返回功能在哪？"

- **组件关联**：
  - "页面组件在哪？"
  - "布局文件在哪？"
  - "模板文件在哪？"

### 核心文件类型
- `*.ets` - 页面组件文件
- `router` - 导航配置
- `navigation` - 导航组件
- `AppStage.ets` - 应用入口

### 搜索策略
1. 搜索`@Entry`装饰器标识的页面文件
2. 查找`router.push()`, `router.back()`等导航调用
3. 识别`Navigation`组件使用位置

### 问题特征

- **语义**：询问数据管理和存储逻辑的实现位置

### 典型问题模式
- **数据存储**：
  - "用户数据存储在哪？"
  - "本地存储在哪实现？"
  - "缓存逻辑在哪？"
  - "数据持久化在哪？"

- **状态管理**：
  - "全局状态管理在哪实现？"
  - "状态更新逻辑在哪？"
  - "数据同步在哪？"
  - "状态监听在哪？"

- **配置管理**：
  - "应用配置在哪？"
  - "用户偏好设置在哪？"
  - "配置文件在哪？"

### 核心文件类型
- `AppStorage` / `AppStorageV2` - 全局状态管理
- `LocalStorage`（V1；V2 用 `@Provider`/`@Consumer`，无 LocalStorageV2） - 页面树状态管理
- `PersistentStorage` / `PersistenceV2` - 持久化
- `Preferences` - 偏好设置
- `RelationalStore` / `RdbStore` - 关系数据库
- `stores/` / `viewmodel/` - 状态管理目录
- `models/` - 数据模型目录

### 搜索策略（V1+V2 兼容）
1. 搜索状态装饰器：`@State|@Local`、`@Prop|@Param`、`@Link|@Event`、`@Observed|@ObservedV2`、`@ObjectLink|@Trace`、`@Provide|@Provider`、`@Consume|@Consumer`
2. 搜索全局/持久化 API：`AppStorage.(create|get|set)|AppStorageV2.connect|PersistentStorage|PersistenceV2.globalConnect`、`Preferences.get`
3. 搜索监听/派生：`@Watch|@Monitor|@Computed`
4. 识别数据模型定义和接口

## 问题类型识别指南

### 关键词匹配表（带 V1+V2 装饰器映射）
| 问题类型 | 关键词 | 语义特征 | V1+V2 装饰器 grep 模式 |
|---------|--------|----------|----------------------|
| 页面导航 | 页面、界面、路由、导航、跳转、返回 | UI界面或导航路径 | `@Entry`、`@Component(V2)?\b` |
| 数据存储 | 数据、存储、状态、缓存、持久化、配置 | 数据管理或存储 | `@State\|@Local`、`@StorageLink\|AppStorageV2`、`PersistentStorage\|PersistenceV2` |
| UI组件 | 组件、按钮、输入框、弹窗、布局、样式 | UI元素或交互 | `@Component(V2)?\b`、`@Builder`、`@Styles`、`@Event` |
| API网络 | API、接口、网络、请求、HTTP、服务 | 网络通信或服务 | `http.createHttp`、`request`、`fetch` |
| 业务逻辑 | 逻辑、算法、计算、处理、业务、规则 | 核心业务或算法 | `class.*Service\|Manager`，V2 还可关注 `@Computed`（派生状态） |
| 配置常量 | 配置、常量、枚举、参数、设置、选项 | 配置或常量定义 | `const`、`enum`、`readonly` |
| 事件生命周期 | 事件、生命周期、初始化、创建、销毁、回调 | 事件或状态管理 | `aboutToAppear\|aboutToDisappear\|onShow\|onHide`，`@Watch\|@Monitor` |
| 权限安全 | 权限、安全、验证、认证、检查、加密 | 安全或权限控制 | `requestPermissionsFromUser`、`ohos.permission` |

### 问题分类流程
1. **提取关键词**：从问题中提取相关关键词
2. **语义分析**：分析问题的语义和意图
3. **匹配类型**：匹配到8大类问题类型中的一类
4. **确定方向**：确定搜索和定位的具体方向

### 特殊情况处理
- **混合问题**：当问题涉及多个类型时，选择主要类型作为主导，其他类型作为补充
- **模糊问题**：当问题不够具体时，要求用户提供更多信息
- **新功能问题**：当询问新功能实现时，基于现有架构推断可能位置
