## 文档说明 

本文档用于说明 CS2 P2P SDK 的主要接口能力、接口分组和基础调用流程,帮助开发 者了解使用 SDK API 的基本使用方式。 

## SDK 接口能力概览 

##### SDK 按照功能大致划分为以下几个模块: 

|模块|功能说明|
|---|---|
|基础管理 接口|用于SDK版本查询、初始化、反初始化和运行信息查询|
|网络检测 接口|用于检测当前网络状态、平台服务器连通性及网络类型|
|设备侧接 口|用于设备上线、监听客户端连接、检测设备在线状态及启用设备辅 助能力|
|客户端接 口|用于客户端发起设备连接、中断连接请求|
|会话管理 接口|用于检测连接状态、关闭连接和释放会话资源|
|数据收发 接口|用于设备端与客户端之间进行双向数据读写,支持保证送达与不保 证送达两类数据收发方式|
|缓冲区检 测接口|用于检测连接通道的读写缓冲区状态,辅助业务进行流控处理|

## 主要接口说明 

### 基础管理接口 

接口 功能说明 `PPCS_GetAPIVersion` 获取 SDK API 版本信息 获取 SDK 运行状态、初始化状态和部分连接状态 `PPCS_GetAPIInformation` 信息 `PPCS_Initialize` 初始化 SDK,加载平台连接配置并准备运行资源 `PPCS_DeInitialize` 反初始化 SDK,释放 SDK 占用的运行资源 

SDK 初始化所需的平台参数、授权信息及安全配置,请联系尚云互联技术支持获取项 目交付配置。 

网络检测接口 接口 功能说明 `PPCS_NetworkDetect` 检测当前网络与 P2P 平台之间的连通状态 `PPCS_NetworkDetectByServer` 基于指定平台服务器信息进行网络检测 

网络检测结果可用于判断当前网络是否具备远程连接条件,并辅助设备端处理网络异 常、重连或重新登录等场景。

接口 功能说明 `PPCS_Listen` 设备端登录平台并监听客户端连接 `PPCS_Listen_Break` 中断设备端监听流程 `PPCS_LoginStatus_Check` 检查设备端登录状态 `PPCS_Share_Bandwidth` 启用或关闭设备转发能力 `PPCS_Enable_SmartDevice` 启用或关闭智能设备辅助连接能力 设备侧接口主要用于设备上线、等待客户端访问,以及在特定业务策略和网络条件下 启用辅助连接能力。 客户端接口 接口 功能说明 `PPCS_Connect` 客户端根据目标设备标识发起连接 `PPCS_ConnectByServer` 客户端基于指定平台服务器信息发起连接 `PPCS_Connect_Break` 中断当前正在进行的连接请求 客户端接口主要用于 App 或其他用户终端发起设备远程访问。连接成功后,SDK 返回 会话标识,开发者可基于该会话进行数据收发和状态检测。 会话管理接口 接口 功能说明 `PPCS_Check` 查询当前会话状态、连接模式和连接信息 `PPCS_Close` 正常关闭会话并释放会话资源 `PPCS_ForceClose` 强制关闭会话并释放会话资源

### 数据收发接口 

SDK 提供两类数据收发接口。 `PPCS_Write` / `PPCS_Read` 用于按写入顺序传输并保 证送达的数据; `PPCS_PktSend` / `PPCS_PktRecv` 用于不保证送达的数据收发。 

|类型|发送接口|接收接口|传输特性|适用场景|
|---|---|---|---|---|
|保证 送达|`PPCS_Write`|`PPCS_Read`|按写入顺 序传输, 保证送达|音视频码流、控 制指令、业务数 据|
|不保|||不保证送|状态通知、低延|
|证送|`PPCS_PktSend`|`PPCS_PktRecv`|达,实时|迟控制、可容忍|
|达|||性优先|丢包的数据|

其中, `PPCS_Write` / `PPCS_Read` 的使用方式接近 TCP Socket 的读写模型。连接建 立后,开发者可基于会话通道完成双向数据收发。

建立连接 建立  P2P  会话
Listen() / Connect() PPCS_Listen() / PPCS_Connect()
数据收发 保证送达的数据收发

接口使用习惯接近  TCP Socket :连接建立后通过  Read / Write  完成数据收发,数据按写入顺序传输并保证送达。

缓冲区检测接口 接口 功能说明 `PPCS_Check_Buffer` 查询指定会话通道的读写缓冲区状态 

缓冲区检测接口可用于判断当前通道的数据积压情况,辅助业务侧进行码率调整、发 送节奏控制、丢帧策略或网络异常处理。

## HarmonyOS 接入说明 

CS2 P2P SDK 主要面向底层连接与数据传输能力。为兼顾实时音视频传输的性能要求 与 HarmonyOS 应用侧接入便利性,SDK 提供 Native API 与 ArkTS 封装接口两种调用 方式:Native API 承载 P2P 连接、会话通道管理和数据收发等核心能力;ArkTS 封装 接口用于在应用层完成初始化、网络检测、连接管理、状态查询等常用操作。 

在典型 HarmonyOS 客户端集成场景中,应用侧可通过 ArkTS 封装接口完成 SDK 生命 周期管理和连接流程编排,并根据业务需要调用连接与读写接口完成数据收发。

### 典型调用流程 

HarmonyOS 应用侧通常作为客户端发起设备连接。SDK 初始化完成后,应用侧可基 于目标设备标识建立会话,并通过会话通道完成数据收发、状态检查和资源释放。 

SDK  准备 连接准备 建立会话
获取  SDK  管理实例 初始化  SDK 发起设备连接
P2PSDK.getInstance() initializeP2P(initString) PPCS_Connect(...)
配置应用上下文 执行网络检测 检查会话状态
configP2PSDK(context) networkDetect(...) checkSession(session)
数据传输 关闭释放
数据写入  /  数据读取 关闭会话
PPCS_Write / PPCS_Read PPCS_Close(session)
检测缓冲区状态 释放  SDK  资源
PPCS_Check_Buffer(...) deInitializeP2P()

连接成功后,SDK 返回会话标识,后续的数据收发、缓冲区检测和连接关闭均基于该 会话进行。异常处理策略可结合业务场景按返回值处理。 

### 常见返回值说明 

ArkTS 侧接口通常采用数值形式返回执行结果。 

|返回值类型|说明|
|---|---|
|`0`|通常表示接口调用成功|
|`> 0`|在连接或写入类接口中,通常表示会话标识或实际写入字节数|
|`< 0`|表示异常或错误状态|

常见异常包括 SDK 未初始化、参数无效、目标设备不在线、连接超时、会话无效、远 端关闭连接、本地关闭连接、会话超时、远端缓冲区已满等。业务侧应根据返回值类 型进行重试、重连、关闭会话或提示用户等处理。
