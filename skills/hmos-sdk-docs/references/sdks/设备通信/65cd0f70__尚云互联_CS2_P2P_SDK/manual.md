- **文档用途:** 帮助开发者了解 CS2 P2P SDK 的接入准备、工程集成、初始化、网络检测、设 备连接、数据收发、关闭释放及常见问题处理方式。 

## 1. 产品概述 

CS2 P2P SDK 面向物联网智能设备远程连接与实时音视频传输场景,提供设备端与 App 等用户终端之间的 P2P 数据传输能力,支持设备远程访问、实时预览、音视频数 据收发和远程控制等功能。 

在 HarmonyOS 应用侧,CS2 P2P SDK 以 Native 动态库为核心提供底层连接与数据 传输能力,并提供 ArkTS 侧接口声明与示例封装,便于开发者在应用层完成调用。考 虑到 P2P 连接、会话通道管理和实时音视频数据收发对性能、线程调度和业务适配有 较高要求,SDK 不以通用 HAR 组件方式封装全部业务流程;接入方可根据自身应用架 构和业务场景,基于 SDK API 进行二次封装和集成。 

- Native **能力** :承载底层 P2P 连接、会话通道管理、数据收发等核心传输能力。 

- ArkTS **接入能力** :提供 ArkTS 侧接口声明和示例封装,便于 HarmonyOS 应用进 行初始化、网络检测、连接流程编排、会话状态查询等操作。 

#### 典型业务场景包括: 

- 智能摄像头远程预览; 

- 智能门锁远程访问; 

- 智能猫眼、智能门铃等设备的数据交互; 

- 设备远程控制、状态查询和音视频业务传输。

## 4. 安装和工程集成 

### 4.1 集成 SDK 文件 

将 SDK 包中的 Native 动态库、ArkTS 声明文件及封装代码加入 HarmonyOS 应用工 程。具体目录结构可根据项目工程配置进行调整。 

需要集成以下内容: 

|文件类型|说明|
|---|---|
|Native动态库|提供底层P2P连接、会话管理和数据收发能力|
|ArkTS声明文件|用于在ArkTS层调用Native能力|
|ArkTS封装代码|用于管理SDK初始化、网络检测、会话状态等应用侧流程|
|示例代码|用于参考初始化、连接、读写和资源释放的调用方式|

完成文件集成后,开发者可在 ArkTS 层导入 SDK 相关模块,并根据业务流程调用 SDK 封装能力。 

### 4.2 配置网络权限 

CS2 P2P SDK 需要使用网络访问能力,用于连接建立、网络检测、会话通信和数据收 发。 

在 HarmonyOS 工程的 `module.json5` 中配置网络权限: 

```
{
"name": "ohos.permission.INTERNET"
}
```

如接入方应用因自身业务需要获取网络状态、Wi-Fi 状态或其他系统信息,应由接入方 根据实际业务场景另行配置,并在自身权限说明和隐私政策中进行说明。

## 5. 功能操作指南 

### 5.1 配置应用上下文 

在使用 SDK 前,建议先获取 SDK 管理实例,并配置 HarmonyOS 应用上下文。 

```
constp2pSDK=P2PSDK.getInstance()
p2pSDK.configP2PSDK(context)
```

#### 说明: 

- `P2PSDK.getInstance()` 用于获取 SDK 管理实例。 

- `p2pSDK.configP2PSDK(context)` 用于配置 HarmonyOS 应用上下文,便于 

- SDK 进行初始化、本地配置管理及相关操作。 

### 5.2 初始化 SDK 

在发起设备连接前,需要先初始化 SDK。 

```
constinitResult=p2pSDK.initializeP2P(initString)
```

#### 说明: 

- `initString` 为项目对应的平台连接配置参数。 

- 初始化成功后,应用侧可继续执行网络检测、设备连接和数据收发等操作。 

- 初始化异常时,可根据返回值判断原因并进行处理。 

建议: 

- 在用户同意应用隐私政策后再初始化 SDK。 

- 不建议在应用未使用设备连接能力时过早初始化 SDK。 

- 若业务仅在用户点击“实时预览”“远程访问”等功能后才需要连接设备,可在用户触 发相关功能后再进行连接流程。 

### 5.3 网络检测 

- 网络检测用于判断当前网络与 P2P 平台之间的连通状态,可在发起设备连接前调用。

### 5.4 发起设备连接 

HarmonyOS 应用侧通常作为客户端发起设备连接。开发者可通过 SDK 封装的连接能 力,根据目标设备标识建立与设备端之间的会话。 

#### 说明: 

- 目标设备标识、连接配置及相关参数应按项目交付配置使用。 

- 连接成功后,SDK 返回会话标识。 

- 后续数据收发、会话状态检查和连接关闭均基于该会话标识进行。 

- 连接异常时,应根据返回值、网络检测结果和业务日志进行排查。 

#### 常见使用场景: 

- 用户点击“实时预览”后连接设备; 

- 用户进入设备详情页后建立远程连接; 

- 用户发起远程控制或音视频数据交互时建立会话。 

### 5.5 会话状态检查 

连接建立后,可通过会话状态检查能力查询当前会话的连接状态、连接模式和会话信 息。 

```
constsessionInfo=p2pSDK.checkSession(session)
```

#### 说明: 

- `session` 为连接成功后返回的会话标识。 

- 返回会话信息时,表示当前会话可用于后续数据收发或状态判断。 

- 返回为空或查询失败时,业务侧应根据实际场景进行重连、关闭会话或提示用户。

### 5.6 数据收发 

#### SDK 提供两类数据收发方式: 

|类型|传输特性|适用场景|
|---|---|---|
|保证送达|按写入顺序传输,保证 送达|音视频码流、控制指令、业务数据|
|不保证送 达|实时性优先,不保证送 达|状态通知、低延迟控制、可容忍丢包的 数据|

开发者可根据业务对实时性、可靠性和数据完整性的要求选择合适的数据收发方式。 说明: 

- 保证送达的数据收发适用于需要顺序性和完整性的业务数据。 

- 不保证送达的数据收发适用于实时性优先、可接受丢包的数据场景。 

- 两类数据收发方式应按 SDK 约定成对使用,不支持混用读取。 

- 对于实时音视频业务,建议结合网络状态和业务码率策略进行发送节奏控制。 

### 5.7 缓冲区检测 

缓冲区检测能力可用于判断当前通道的数据积压情况,辅助业务侧进行发送节奏控 制、码率调整、丢帧策略或异常网络处理。 

建议使用场景: 

- 连续发送音视频数据时,检测写缓冲区是否持续积压; 

- 网络波动时,判断是否需要降低码率或调整发送频率; 

- 业务侧需要进行流控或异常网络处理时,辅助判断当前通道状态。 

### 5.8 关闭会话 

业务结束、连接异常或应用退出时,应及时关闭会话并释放会话资源。 

说明: 

- 正常结束远程访问时,应关闭当前会话。 

- 连接异常或页面退出时,应结合业务状态及时释放会话资源。

### 5.9 释放 SDK 资源 

当应用不再需要使用 P2P 能力时,可释放 SDK 运行资源。

- 用户退出设备远程访问页面; 

- 业务流程结束且不再需要保持连接; 

- 应用需要重新初始化 SDK 配置。

## 8. 常见问题解答 

### Q1:初始化 SDK 失败怎么办? 

请检查以下内容: 

- 平台连接配置是否正确; 

- SDK 文件是否已正确集成; 

- 应用上下文是否已完成配置; 

- 是否重复使用不同配置初始化 SDK; 

- 是否已按照项目要求配置运行环境。 

### Q2:如何选择保证送达和不保证送达的数据收发方式? 

如业务需要顺序性、完整性和送达保障,建议使用保证送达的数据收发方式。如业务 更关注实时性,并可接受丢包,可使用不保证送达的数据收发方式。

- 设备转发、低功耗远程唤醒等能力应结合实际项目方案、网络条件和用户授权情况 使用。
